# Developer guide

This guide describes the source preview in `ecosystem/`. Start with its README
for tested install/test commands and each package's README for implemented
entrypoints. A proposed command in an older handoff is not a released API.

Choose a connector when you own a file format and final serializer; choose an
extension when you add operations/views through an existing connector's
document API. Data/preset packages provide references/composed operations but
cannot grant construction, entitlement or publication permission. Keep new
levels, factions, maps, vehicles or other domains inside the plugin API; do not
add game-specific host pages.

Use the wholly synthetic connector and separate progression extension first.
Build an exact package and execution lock, select only your local fixture,
inspect it, stage an operation, review the intended semantic diff and validate
the reopened candidate. Only one connector serializes a final payload. CAS and
operation-domain conflict checks prevent stale/overlapping edits from silently
replacing one another.

Custom UI may be a graph, canvas, map or complete application. Use the
framework-neutral bridge and packaged assets; do not fetch external scripts or
reach into the parent DOM/cookies. UI-origin/window/instance/sequence checks
and bounded messages are required alongside package review. The trusted
approval surface remains outside your frame.

Private fixtures are opt-in workspace inputs. Use only saves you have the
right to inspect, and separately authorize bounded AI inspection if requested.
Do not put credentials, account exports, owner saves, HAR files, signed URLs or
private fixture payloads in source/release/issue attachments. Missing
private-fixture checks must be reported `not_run`, not passed.

For Crimson, review its source map, schema assumptions, exact-key namespaces,
unknown-header/list-marker preservation and external data requirements.
Numerical item/character IDs are different namespaces. Standard native LZ4,
HMAC, wrapper boundaries, paired payloads and independent validation matter;
the historical literal-only compression failure must not be reintroduced.
Reference names/art do not prove game semantics or entitlement ownership.

See [CONTRIBUTING.md](./CONTRIBUTING.md), [SECURITY.md](./SECURITY.md) and
[RELEASING.md](./RELEASING.md) before submitting a plugin.
